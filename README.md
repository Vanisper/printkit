# printkit

一个独立、跨平台、可扩展的本地打印系统，为 Web、桌面应用和自动化流程提供统一的打印能力。

printkit 围绕可复用的打印核心构建后台服务、桌面管理工具和不同形式的接入端。它可以独立使用，也可以与 [weblauncher](https://github.com/Vanisper/weblauncher) 等程序组合部署。

## 当前状态

项目处于需求梳理与技术验证准备阶段，目前只有立项文档，没有可运行的打印实现。Windows、macOS、Linux 是目标平台，实际支持范围需要通过操作系统版本、驱动和机型验证确定。

核心语言、渲染引擎、桌面框架、分发方式和开源许可证尚未确定。

## 从什么问题出发

现有业务 Web 已经通过打印样式、克隆打印区域到 iframe、调用 `window.print()` 实现单据打印。业务侧能够决定单据内容，但打印交互仍受浏览器预览窗口控制，任务状态反馈有限，低配置客户机也可能出现明显等待。

printkit 的首个落地场景是保留这些业务单据的排版资产，让业务页面异步提交打印任务，由本地系统负责渲染、调用驱动和提供可查询的执行状态。

## 产品目标

- 支持 Windows、macOS、Linux，覆盖已登录和无人登录运行场景
- 优先通过操作系统驱动接入 USB 与局域网打印机
- 为获得授权的应用提供静默打印、设备选择和任务状态查询
- 支持已有 HTML/CSS 单据接入，也接受已排版的 PDF 等文档
- 让 Web 接入、桌面管理、CLI 和后续远程连接器共享打印能力
- 在目标低配置设备上验证响应、资源占用、排版质量和故障恢复

这些是目标，不是已实现能力。“更好”需要通过相同文档、设备和运行条件下的对比验证。

## 第一阶段

以一份真实结构的双联单和一份汇总单为样本，验证“源文档 → 打印产物 → 系统打印队列 → 状态回传”的完整路径。分别验证 HTML 渲染与驱动打印，在三平台及无人登录环境下取得证据后，再确定实现技术栈和支持矩阵。

首阶段不依赖中央任务服务器或模板设计器。二者仍是可独立发展的后续能力。
