# printkit

printkit 是一个独立的本地打印系统，为 Web、桌面应用和自动化程序提供可复用的打印能力。

当前目标是：**让现有 Web 单据在一套真实客户机环境中静默打印，页面可以继续操作，业务可以查询任务进展和失败原因。**

项目目前只有设计和调研文档，尚无可运行实现。最小原型已选定 Go、Chrome 和 SQLite，先在 macOS 开发机验证软件链路；真实打印平台和设备验收在有可用打印机后推进。

## 从现有单据开始

业务系统已经能够生成双联单和汇总单：用打印 CSS 处理排版，将打印区域克隆到 iframe，再调用 `window.print()`。现有问题集中在浏览器打印交互、有限的状态反馈，以及低配置客户机上的等待。

printkit 首先复用这些单据的内容和排版规则，将最后一步改为向本地程序提交任务。业务负责形成打印稿，本地程序负责后续渲染、驱动调用和执行记录。

## 当前原型

目前没有可用打印机，先完成“Web 提交 → 持久化 → HTML 生成 PDF → 状态查询与下载”，已有 PDF 直接保存。结果分别显示“已生成 PDF”或“已保存 PDF”。

采用 Go 本地服务、chromedp 驱动独立 Chrome、SQLite 存储和 HTTP 轮询，提供简单验证页面。任务去重、页面关闭后的执行和重启恢复一并验证，具体见 [最小原型方案](docs/design.md)。

## 首个可用打印版本

先选定一套实际使用的操作系统、浏览器、打印机和驱动，完成以下能力：

- 接收现有单据的 HTML/CSS 和必要资源，也接受已排版的 PDF
- 选择系统打印队列，明确纸张、方向、份数等设置
- 向已授权的业务应用提供异步提交，持久化受理后返回任务编号
- 在后台静默执行，网页关闭后仍能处理已受理的任务
- 查询执行进展和错误，区分系统队列反馈与结果待确认，支持人工补打

以一份双联单和一份汇总单验收内容、分页、纸面输出及异常恢复，并在同一台客户机上对比原有流程的页面响应、耗时和资源占用。

## 后续方向

Windows、macOS、Linux，USB 与局域网打印机，以及无人登录运行，仍是产品目标。实现顺序按实际部署需求安排，支持范围按已验证的系统、驱动和机型记录。

| 阶段 | 重点 |
| --- | --- |
| 跑通单据 | 在一个真实环境完成文档提交、静默打印和状态查询 |
| 扩大运行范围 | 验证后台服务、冷启动未登录、其他平台及设备组合 |
| 扩展使用方式 | 桌面管理、CLI / SDK、远程任务派发、Web 拖拽模板设计 |

模板设计器、中央任务服务和完整桌面管理端留待对应场景推进。首个版本优先复用现有业务打印稿，通过系统驱动输出。

printkit 独立开发，可以与 [weblauncher](https://github.com/Vanisper/weblauncher) 组合安装、提供配置入口；打印服务保持独立运行。
