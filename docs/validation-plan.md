# printkit PoC 验证计划

**状态：验证计划尚未执行。**本文没有实测结果，也不代表三平台、全部系统驱动或无人登录打印已经可用。
先验证最小打印链路，再冻结客户端语言、渲染器和发布方式；性能阈值在取得现有方案基线后共同确定。

## 1. 验证对象与术语

本文使用 [领域术语](../CONTEXT.md) 中的定义。验证分别覆盖源文档到打印产物、打印产物到系统队列，以及系统队列到物理输出的证据范围。

PoC 使用现有双联单、汇总单作为真实业务样本，并补充长表格、中文字体、图片、条码和异常资源样本。
样本使用脱敏数据，保留源文档、打印意图、打印产物、版本、日志、纸面照片和人工核对记录。
缺少机器或打印机的矩阵项标记为“未验证”，不得用虚拟打印机结果替代物理打印验收。

## 2. 环境与执行矩阵

| 维度 | 必测组合与记录 |
| --- | --- |
| 操作系统 | Windows、macOS、Linux；记录版本、架构，Linux 另记发行版 |
| 客户机硬件 | 包含代表性低配置客户机；记录 CPU、内存、存储、后台负载及电源模式 |
| 打印连接 | 各平台实际 USB 与 LAN 系统队列；记录机型、驱动及连接协议 |
| 打印机 | 实际使用的办公打印机与标签／票据打印机，支持范围以实测为准 |
| 运行身份 | 普通登录用户、服务实际运行账号；记录队列可见性与访问权限 |
| 会话状态 | 已登录、锁屏、退出登录、冷启动后从未登录桌面 |
| 浏览器入口 | 目标版本 Chrome、Edge、Firefox、Safari；按平台列出适用组合 |
| 负载 | 单任务、连续任务、并发入口、长文档；规模依据真实样本确定 |

先建好系统打印队列，并用系统可用方式确认设备和驱动能打印；此结果只作为环境检查。
每次执行记录构建版本、渲染器版本、驱动配置、字体、设备绑定、运行身份和网络条件。
每项检查分别记录“通过／失败／未执行／不适用”；不适用必须有原因，不作为通过统计。

## 3. 建立现有方案基线

1. 固定现有 DOM 克隆、print CSS 和 `iframe.contentWindow.print()` 的业务版本及样本。
2. 在代表性低配置客户机上，以相同机器、打印队列、纸张和样本对比新旧流程，保存生成内容与纸面结果。
3. 分开记录页面采集、浏览器排版、打印对话框、系统提交与首张出纸，人工停留时间单列。
4. 检查交互卡顿出现在哪一阶段；记录页面主线程长任务及打印期间交互响应。
5. 冷态与暖态分别多次运行，保存原始值和波动；样本数量确定后再计算分位值。

若浏览器无法暴露某段耗时，明确写“不可直接观测”及测量代理量，不倒推出虚假的精确时间。
新旧流程必须比较相同边界；静默流程省去人工确认的时间不能冒充渲染性能提升。

## 4. 先验证 PDF 原生打印后端

此阶段使用固定、已人工核对的 PDF，绕过 HTML 渲染器，单独检验打印产物到物理设备的链路。

1. 按设备绑定枚举并选择系统队列，读取可获得的纸张、方向、份数、单双面等能力。
2. 提交固定 PDF，记录采用的 PDF 解码／绘制路径、驱动接口、系统任务标识和状态证据。
3. Windows 明确实现 PDF 到驱动可接受内容的转换；不得假定 RAW 写入会替应用渲染 PDF。
4. macOS／Linux 记录 CUPS 实际接收格式、转换依赖和队列配置，不把安装 CUPS 等同于 PDF 可打印。
5. 核对实际纸张尺寸、缩放、边距、方向、页序、份数、裁切及条码可读性。
6. 对不支持的打印意图给出明确结果，不静默改用默认纸张、默认打印机或不同单双面设置。
7. 分别执行正常、缺纸、离线、暂停队列、USB 拔插、LAN 中断及取消操作，保存原始反馈。

通过条件：指定设备能按支持的打印意图输出，状态能够追溯；无法确认的设备能力明确标为未知。
切纸、钱箱等扩展能力单列，不用 PDF 普通页面打印的成功推定这些动作可用。

## 5. 独立验证 HTML 渲染迁移

此阶段只验收源文档到 PDF，不连接物理打印机；优先复用当前业务生成的 HTML 与 print CSS。

1. 采集双联单和汇总单，固定表单当前值、展开状态、图片、字体、样式及相对 URL 的解析基准。
2. 逐项检查 canvas、blob URL、跨域资源、伪元素及 iframe；不能仅凭 `outerHTML` 宣称采集完整。
3. 定义资源就绪信号及超时规则，验证字体／图片慢加载和失败；禁止静默生成缺内容产物。
4. 在候选渲染器中固定视口、纸张、缩放、页边距、字体与版本，执行 print media 排版。
5. 对照基线核对两联内容、联次标记、分页、页眉页脚、汇总数据、长表格跨页和空白页。
6. 将 PDF 栅格化作视觉对照，并人工检查关键文本、条码与分页；差异必须解释且得到业务认可。
7. 验证受限网络、离线资源包、异常 HTML、超大文档、渲染超时和 worker 崩溃后的隔离效果。

通过条件：业务样本内容完整、布局差异可接受，失败可定位；不得因使用同一家浏览器内核免除对照。
独立 worker 的隔离收益和总耗时分别测量；降低业务页面卡顿不等于降低整机 CPU 或缩短出纸时间。

## 6. 验证后台服务与无人登录

1. 为 Windows 服务、macOS LaunchDaemon、Linux 系统服务分别记录安装方式、账号及工作目录。
2. 在已登录状态跑通固定 PDF，再跑 HTML 渲染与打印完整链路，避免把两类故障混在一起。
3. 锁屏后重复执行，仅记录为锁屏测试；随后退出桌面登录，确认任务不依赖托盘进程存活。
4. 冷启动后不登录桌面，通过受控入口或预置任务触发打印；保存启动、渲染、提交和纸面证据。
5. 分别验证开机已有待处理任务与无人登录期间新进入的任务，确认资源不依赖此前浏览器会话。
6. 检查服务身份下的队列、字体、缓存、临时目录、网络凭据及权限，不能借用交互用户环境掩盖问题。
7. 重启服务和机器后检查恢复；若系统解密或启动前必须人工操作，明确记录该前置条件。

隐藏窗口、启动托盘和无头 CI 运行都不能替代上述无人登录测试；虚拟显示服务若被采用，必须列为部署依赖。
通过条件：每个声称支持的平台都完成冷启动未登录测试，且没有自动登录或人工启动 GUI 的隐含步骤。

## 7. 验证任务、执行尝试与状态证据

1. 同一请求标识重复提交、并发提交和服务重启后重放，确认持久化去重；不同内容复用标识应被拒绝。
2. 在领取前、产物生成后、提交前、提交中、系统接受后但本地记录前分别注入进程崩溃。
3. 对提交中和提交后证据不完整的执行尝试标记“结果待确认”，不得按超时自动再次打印。
4. 验证只在确定尚未提交或已明确拒绝且无打印副作用时自动重试，并保留每次执行尝试记录。
5. 人工补打创建新打印任务并关联原任务，记录原因、操作者、源文档和打印产物，不覆盖原历史。
6. 系统任务排队、处理中、已移出队列和设备物理完成分级展示，保存状态证据的来源与可确认范围。
7. 用人工纸面核对验证出纸结果；API 成功、队列消失或系统任务完成不能自动升级为物理完成。
8. 测试部分出纸、取消与提交竞态、同设备并发及设备绑定失效，确认没有静默换机或整单盲目重打。

通过条件：任务历史可追溯、未知状态不被伪装成成功，且故障注入没有触发无法解释的自动重复打印。

## 8. 验证 Web 授权与本机入口

1. 在目标浏览器测试 HTTPS 业务站点访问 loopback 的实际行为，记录安全上下文、CORS 及本地网络访问提示。
2. 验证首次授权、授权来源绑定、凭据有效期与撤销；CORS、端口可达或请求自带 Origin 都不等同于授权。
3. 使用未授权站点、伪造来源、过期凭据和跨用户请求验证拒绝行为；授权不得依赖无人登录时弹出界面。
4. 验证重放请求、超大载荷、任意路径、外部资源访问及可执行命令注入，确保入口只接受定义好的打印协议。
5. 验证端口冲突、服务未启动、服务升级与浏览器限制变化的错误反馈，避免业务页面一直等待或绕过授权。

通过条件：受信任入口可用且拒绝未授权调用；桌面 UI、Web 桥及其他宿主遵循同一任务协议和访问边界。

## 9. 性能记录与技术冻结门槛

统一记录采集开始／结束、源文档接收、渲染开始／结束、系统提交开始／返回、首张出纸及可确认的完成时间。
同时记录页面卡顿、队列等待、各进程 CPU、峰值／稳态内存与任务结束后的回落；注明冷暖条件及进程是否复用。
先形成可复查的原始数据和新旧基线对照，再确定业务可接受的耗时、内存和波动阈值，本文不预填数字。

以下门槛未通过时保留候选方案，不冻结 Go／Rust／Zig、渲染器或宣称通用支持：

- 原生后端在代表性系统驱动、USB／LAN 队列上准确打印
- 双联单、汇总单迁移后满足内容和分页验收
- 三平台完成冷启动未登录的完整链路验证
- 提交中崩溃、持久化去重、未知状态及补打关系通过故障注入验证
- Web 来源授权、目标浏览器兼容性和本机入口访问边界通过验证
- 性能对照满足取得基线后约定的目标，构建、安装与升级依赖可以接受

最终报告附每个矩阵项的结果、证据链接、已知限制和未覆盖范围，再决定首批支持清单与实现技术栈。
